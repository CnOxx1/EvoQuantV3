## 新的数据治理能力

每个可回填表现在都可由 `audit_data_coverage_and_queue_backfills.py` 审计。审计按合约或指标分区输出行数、最早/最新事件时间、预期时间间隔、缺口数和最大间隔，并将缺口登记到 `market_data.db.data_backfill_tasks`。

| 队列状态 | 当前数量 | 含义 |
|---|---:|---|
| `pending` | 0 | 已检测到但尚未尝试补采的缺口。 |
| `source_omission` | 4 | 已按建议命令完整重试，公开上游仍不返回相应日期；保留事实状态，不重复无效请求。 |
| `resolved` | 0 | 未来重跑补齐缺口后可人工登记。 |
| `failed` | 0 | 任务执行错误时使用，附带失败原因。 |

该机制不会把数据源省略日期自动填零，也不会用相邻值插补。对于上游源缺失，报告仍保持 `attention`，使研究层或下游使用者可以过滤、停用或另择合法来源，而不是获得虚假的“完整”标签。

## 运行方式

以下命令均在项目虚拟环境中直接运行 Python，不依赖 PowerShell 重定向逻辑。

```bash
# 90 日市场与衍生品历史；均支持幂等重跑
.venv\Scripts\python.exe scripts\collect_okx_market_history.py --days 90 --bar 1H
.venv\Scripts\python.exe scripts\collect_okx_funding_history.py --days 90
.venv\Scripts\python.exe scripts\collect_deribit_funding_history.py --days 90 --chunk-hours 168

# 覆盖、连续性和补采状态
.venv\Scripts\python.exe scripts\audit_data_coverage_and_queue_backfills.py
.venv\Scripts\python.exe scripts\audit_active_domain_freshness.py
.venv\Scripts\python.exe scripts\verify_public_data_coverage.py
```

## 已知边界

Ethereum 已具备免费公开的交易、区块和手续费快照，但目前**没有**被宣称为活跃地址历史或完整的逐日链上面板。Bitcoin 仍以公开 Charts 的实际返回为准；四个日期缺口已经由一次完整重试确认，并显式登记为上游省略。地址归因、完整地址 PnL、私有账户数据、商业授权数据和需 API Key 的浏览器 API 继续排除在免费公共数据基线之外。
