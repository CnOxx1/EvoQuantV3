# EvoQuant 数据层覆盖契约

本契约将“端到端量化的数据层”限定为可自动采集、标准化、落库、审计和恢复的**公开原始事实数据**。本次优化不引入策略、预测、仓位建议、用户账户数据或商业 API Key。

| 数据产品 | 最小覆盖目标 | 时间粒度与连续性 | 免费公开来源 | 质量门槛 |
|---|---|---|---|---|
| OKX 现货与永续 K 线 | BTC/ETH，`BTC-USDT`、`ETH-USDT` 及对应 `-SWAP` | 1 小时；首期目标最近 90 日，后续增量 | OKX `market/history-candles` | 每行保存原始 JSON、来源 URL、事件时间；同一合约相邻有效柱的间隔不得超过 1 个周期。 |
| OKX 资金费率历史 | BTC/ETH 永续合约 | 首期目标最近 30 日或端点实际可用窗口 | OKX `public/funding-rate-history` | 记录原始返回、合约、资金费率时间与分页游标；不得将当前费率伪装成历史。 |
| OKX OI、清算、基差 | BTC/ETH 永续 | 采集时快照及端点可返回的公开窗口 | OKX Public REST | 保持 `kind` 区分，避免将不同口径合并为单一时间序列。 |
| 多交易所报价 | Kraken、Coinbase BTC/USD 和 ETH/USD | 采集时快照 | 两家交易所公开报价接口 | 保留交易所、交易对、bid/ask/last/volume、观察时间和原始响应。 |
| Bitcoin 基础链上历史 | 交易数、活跃地址、手续费 | 日频，近一年及后续增量 | Blockchain.com Charts | 每一个指标独立保留来源字段与日期；缺失日期必须在审计中报告。 |
| Ethereum 网络基础事实 | 24 小时交易数、区块数、手续费与 Gas 相关快照 | 采集时快照；不声称为地址历史 | Blockchair Ethereum Stats（仅在实际无密钥请求成功时） | 保存完整原始 JSON；仅映射实际返回且定义清晰的字段。 |
| 稳定币供应与链分布 | 来源所返回的稳定币与链级供应事实 | 日频快照与已有历史 | DeFiLlama 公开接口 | 保存采集时间、资产/链维度、来源 URL；不将市值变化解释为链上净流。 |

## 数据质量与恢复契约

每个可回填数据集应具备四项元数据：`source_url`、`collected_at`、事件时间或观测时间、以及原始 JSON。可分页历史任务必须另外记录任务标识、覆盖开始/结束、最后成功游标、写入行数与失败原因；重跑相同范围必须幂等。

质量审计至少输出表记录量、每个数据集的最早/最新事件时间、期望间隔、检测到的缺口数量、最近采集时间和失败状态。状态接口只暴露有真实主表记录的公开数据域；计划中但尚未实际验证的源不注册为 active。

## 明确不纳入项

地址级全量活跃地址、鲸鱼归因、完整地址 PnL、私有交易所数据和需要密钥的区块浏览器 API 不属于当前免费公共数据基线。Ethereum 的免费端点若不能稳定提供活跃地址历史，则只记录交易、区块、手续费与 Gas 的实际可用字段，而不生成代理值。
