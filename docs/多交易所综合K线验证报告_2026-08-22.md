# 多交易所综合 K 线验证报告

**验证时间：2026-08-22 11:15 UTC。** 本报告覆盖 EvoQuant 免费公共数据层的 BTC/USD 与 ETH/USD 小时 K 线来源融合。设计目标不是用单一交易所补齐数据，而是在保留每一个交易所原始记录的前提下，只输出可由多个独立公开来源相互佐证的综合时间桶。

> 最终状态目录为 **27 active / 0 empty / 0 disabled / 0 error**。多交易所原始 K 线与综合 K 线均为独立公开数据域。

## 已验证来源与覆盖

| 交易所 | 交易对 | 原始小时 K 线 | 实际覆盖 | 处理方式 |
|---|---|---:|---|---|
| Coinbase Exchange | BTC/USD、ETH/USD | 各 2,160 条 | 最近 90 日 | 以每页最多 300 根的官方公开 REST 窗口分块请求。 |
| Kraken Spot | BTC/USD、ETH/USD | 各 720 条 | 最近约 30 日 | 读取公开 OHLC；丢弃官方说明中“尚未完成”的最后一根。 |
| Bitstamp | BTC/USD、ETH/USD | 各 720 条 | 最近约 30 日 | 读取公开 OHLC，并请求排除当前未完成的 K 线。 |
| 综合 K 线 | BTC/USD、ETH/USD | 各 720 条 | 三来源重叠的最近约 30 日 | 仅在质量门控通过时写入。 |

原始表 `public_exchange_candle_history_raw` 当前共有 **7,200 条**记录；综合表 `multi_exchange_composite_candles` 当前共有 **1,440 条**记录。90 日范围中仅有 Coinbase 的较早时间桶不会被降格为“综合 K 线”，而是保留为 Coinbase 原始数据，并在质量事件表中明确标为 `insufficient_valid_sources`。

## 防止单一交易所异常污染的规则

| 控制项 | 实施方式 | 当前验证结果 |
|---|---|---|
| 原始数据隔离 | 每条记录用 `exchange + pair + bar + open_time_ms` 作为主键，原始 JSON、来源 URL、采集时间永久保留。 | 三家来源均独立可审计。 |
| 最少来源数 | 综合 K 线必须含至少 **2 家**通过校验的交易所；配置不允许设置为 1。 | `single_source_composite_rows = 0`。 |
| OHLC 完整性 | 价格必须为有限正数，且 `high ≥ max(open, close)`、`low ≤ min(open, close)`、成交量非负。 | 不完整或矛盾 OHLC 不进入综合。 |
| 价格偏离 | 先以候选 close 的中位数为中心；close 偏离超过 **100 bps** 的来源写入质量事件并从该桶剔除。 | 当前 BTC 最大通过偏离为 6.13 bps，ETH 为 8.74 bps。 |
| 综合计算 | 通过来源的 open/close 使用成交量权重；high 取最大、low 取最小、volume 求和；同时保存 median close、来源数、最大偏离和原始来源记录。 | 每个当前综合桶均有 3 个通过来源。 |
| 无共识时不输出 | 两家来源明显分歧且都无法组成一致集合时，不生成综合行。 | 单元测试已覆盖双来源分歧拒绝。 |

质量事件表 `multi_exchange_candle_quality_events` 当前记录 **7,200 条**来源评估：其中 **4,320 条**来源通过并进入综合计算，**2,880 条**因 90 日早期只有 Coinbase 单来源而被排除。这里的“排除”是可解释的覆盖不足，而不是删除或修正原始数据。

## 日常运行行为

统一入口 `scripts/run_public_data_layer.py` 现在包含 **19 个**免费公共采集任务。多交易所 K 线任务在日常运行时仅拉取 Coinbase 最近 7 日重叠窗口、Kraken 最近 720 小时以及 Bitstamp 最近 168 小时，然后重建质量门控综合表；初始 90 日 Coinbase 历史通过独立脚本回填，不会在每轮采集重复请求全量历史。

```bash
# 初始历史回填
.venv\Scripts\python.exe scripts\collect_public_multi_exchange_candles.py --coinbase-days 90 --bitstamp-limit 720

# 仅生成并审计综合 K 线
.venv\Scripts\python.exe scripts\build_multi_exchange_composite_candles.py --min-sources 2 --max-deviation-bps 100
.venv\Scripts\python.exe scripts\audit_multi_exchange_candle_quality.py
```

## 已知边界

Kraken 官方公开 OHLC 接口只返回最近 720 根，不能作为 90 日小时 K 线的完整免费补源；Coinbase 的官方文档也明确提示无成交区间可能没有历史桶。[1] [2] 因此，系统不会将 Coinbase 的 90 日单源区间误写为综合数据，也不会填零或插值。Bitstamp 的 API 文档说明其公开数据可用于衍生计算与再分发，但仍应遵守该交易所的服务与许可边界。[3]
